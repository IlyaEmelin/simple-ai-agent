# AGENTS.md — simple-terminal-agent

## Контекст проекта

- Проект: учебный локальный `simple-terminal-agent`.
- Текущая фаза: `5.9.1 terminal Python agent runtime`.
- Цель фазы: собрать маленький терминальный агент с `agent/soul.md`, двумя безопасными tools, agent loop, логом действий и локальной проверкой отказов.

## Источники истины

- Перед кодом читать `spec.md`, agent runtime contract и активный пункт `Plan.md`.
- `Plan.md` хранит текущий шаг, проверки, ошибки и следующий узкий запрос.
- `README.md` или runbook использовать как источник фактических команд.
- Секреты из `.env` не читать, не печатать и не переносить в код, промпты, заметки или README.
- Для AI Studio API объяснять пользователю только названия нужных переменных и место, куда их внести локально: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_MODEL_URI`, `YANDEX_BASE_URL`, `YANDEX_TEMPERATURE`, `YANDEX_MAX_TOKENS`.
- Не просить пользователя присылать реальный API key или содержимое `.env`.

## Рабочие правила

- Работать только в scope учебного терминального агента.
- Выполнять один активный пункт `Plan.md` за раз.
- Перед изменением кода показывать список файлов и план изменений.
- После каждого фрагмента обновлять статус, проверки и ошибки в `Plan.md`.
- Финальный `README.md` / runbook обновлять после проверенного результата, а не до кода.
- Если модель или API недоступны, фиксировать ошибку в `Plan.md` и не менять архитектуру агента.

## Правила runtime

- Системная инструкция агента хранится в `agent/soul.md`.
- Разрешены ровно два tools:
  - `read_markdown_file(path)`;
  - `write_note(filename, content)`.
- `read_markdown_file` читает только `.md` внутри `workspace/`.
- `write_note` пишет только `.md` внутри `notes/`.
- Summary делает модель после чтения файла; отдельного summary-tool нет.
- Runtime обязан проверять имя tool, JSON-аргументы, путь, расширение и выход за разрешённые папки.
- Runtime возвращает результат tool модели через `role: tool`.
- Runtime имеет лимит шагов, чтобы loop не стал бесконечным.

## Вне текущей фазы

- Не создавать Telegram-бота.
- Не добавлять RAG, MCP, web UI, SQLite, базу данных, внешние сервисы, deploy или production-настройки.
- Не выполнять shell-команды через агента.
- Не давать агенту интернет-доступ.
- Не читать `.env` и произвольные файлы проекта.
- Не добавлять долгосрочную память.
- Не создавать больше двух tools без отдельного изменения `spec.md`.
- Не превращать агента в универсального ассистента.
